# 25. Recruiting vs Upskilling

La respuesta habitual es:

```text
ambos
```

**Upskilling**: la persona mantiene su rol y añade capacidades.

Ejemplo:

```text
Backend Developer
+
RAG / LLM APIs / evaluation
→ AI Engineer
```

**Reskilling**: transición sustancial hacia otro rol.

El talento interno aporta conocimiento de:

- dominio;
- datos;
- sistemas;
- procesos reales.

El talento externo aporta experiencia y velocidad, pero debe existir knowledge transfer para no crear dependencia.

# 28. Career Paths

Si IA es solo “el proyecto de moda”, será difícil retener talento.

Conviene ofrecer:

```text
Individual Contributor ladder
Manager ladder
```

sin obligar a expertos técnicos a convertirse en managers.

Promoción basada en evidencia de:

- sistemas entregados;
- calidad;
- mentoring;
- reliability;
- impacto.

Evitar role inflation con títulos llamativos sin responsabilidades claras.

# 31. RACI

RACI:

```text
R Responsible
A Accountable
C Consulted
I Informed
```

Debe haber un Accountable claro y pocos Responsible.

Ejemplo: cambio de prompt crítico:

```text
Product       A
AI Engineer   R
Domain SME    C
Security      C si riesgo
Platform      I
```

Cambio de modelo:

```text
Service Owner A
AI Platform   R
Product       C
Security      C
Risk          C
```

Fuente documental:

```text
Knowledge Owner A
Data Engineer   R
AI Engineer     C
Security        C
```

# 32. Decision Rights

Además de RACI debemos saber:

```text
quién puede aprobar
quién puede bloquear
quién puede hacer rollback
```

ADR y Model Decision Records ayudan a conservar evidencia de decisiones técnicas y de modelo.

# 33. Agile adaptado a IA

La incertidumbre experimental no encaja siempre con un backlog de features.

Separar:

## Discovery

```text
¿qué funciona?
```

## Delivery

```text
construir de forma fiable
```

Un experiment backlog contiene hipótesis:

```text
¿chunk_size 500 mejora Hit Rate@3?
```

Un product backlog contiene capacidades:

```text
el usuario puede ver las fuentes
```

Un risk backlog contiene:

```text
validar ACL antes del retrieval
```

# 39. CI / CD / CT

**CI**:

- code tests;
- data schema;
- pipeline tests;
- model interface.

**CD**:

- promover modelos/servicios/pipelines.

**CT — Continuous Training**:

```text
new data
→ train
→ evaluate
→ promote if accepted
```

No todo sistema necesita CT.

# 45. MLflow

MLflow sigue cubriendo experiment tracking, model lifecycle y evaluación para ML tradicional.

Su stack actual también incluye capacidades para GenAI:

- tracing;

- prompt management;
- LLM/agent observability.

Esto ilustra la evolución desde MLOps hacia LLMOps.

# 48. Kubeflow Pipelines

Kubeflow Pipelines es una plataforma para construir y desplegar workflows ML portables y escalables sobre sistemas Kubernetes.

Un pipeline representa un DAG de componentes.

Es apropiado cuando existen:

- training workflows;
- data pipelines complejos;
- Kubernetes;
- necesidad fuerte de reproducibilidad.

No es requisito automático para una aplicación RAG que utiliza un LLM gestionado.

# 53. Operating Model centralizado

Un único equipo central construye toda la IA.

Ventajas:

- expertise;
- consistency.

Problemas:

- bottleneck;
- poco domain knowledge;
- queue de proyectos.

# 54. Operating Model federado

Cada unidad de negocio tiene equipo propio.

Ventajas:

- velocidad;
- domain ownership.

Problemas:

- duplicación;
- controles inconsistentes;
- proveedores/herramientas distintos.

# 55. Hub-and-Spoke

# 65. Entornos

```text
DEV
STAGING
PROD
```

Dev puede usar datos sintéticos/limitados. Staging debe ser representativo. Prod utiliza datos reales controlados.

No usar datos productivos en desarrollo simplemente por comodidad.

# 66. Immutable promotion

Lo evaluado debería ser lo desplegado.

Evitar:

```text
model=@latest
prompt=@latest
```

si pueden cambiar silenciosamente.

Versionar configuración:

- model ID;
- prompt version;
- index version;
- thresholds.

# 67. Secrets

Separados del código.

Usar:

- secret manager;
- workload identity;
- managed identity.

# 68. Quality Gates

Ejemplo para un RAG:

```text
unit tests pass
Hit Rate@3 >= target
citation validity >= target
ACL tests pass
latency <= SLO
cost <= budget
```

High-risk changes pueden requerir approval humano adicional.

# 69. Canary y Shadow Mode

**Canary**:

```text
5% traffic
→ compare
→ expand
```

**Shadow mode**:

```text
new system receives traffic
but does not affect the user
```

Muy útil para comparar modelos o retrieval sin impacto productivo.

# 70. Rollback

Debe ser rápido para:

- model;
- prompt;
- index;
- agent config.

Operaciones no debe depender de una persona con portátil para desactivar una feature.

# 71. Observabilidad

Pilares:

```text
logs

traces
```

Métricas operativas:

- latency;
- errors;
- availability;
- cost.

Métricas AI:

- retrieval hit;
- groundedness;
- citations;
- tool success.

Métricas de producto:

- time saved;
- task completion;
- escalations.
