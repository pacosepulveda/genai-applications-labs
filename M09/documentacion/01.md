# Módulo 9 — El Futuro de la IA Generativa en la Empresa

**Curso:** Desarrollo de Aplicaciones de IA Generativa  
**Documento:** Documentación técnica del Módulo 9  
**Versión:** 1.0 — 30/09/2026  
**Público objetivo:** perfiles técnicos, arquitectura, producto, datos, seguridad, innovación y responsables de adopción de IA  
**Enfoque:** tendencias emergentes, multimodalidad, agentes, personalización, Edge AI, hardware, nuevas arquitecturas, regulación, sostenibilidad y colaboración humano‑IA

>
> Este documento mantiene exactamente esos ejes y los amplía con el contexto técnico y empresarial necesario para analizarlos con criterio en septiembre de 2026.

# 0. El objetivo de M09 no es predecir el futuro

En tecnología es fácil confundir:

```text
nuevo
=
mejor
=
maduro
=
adecuado para producción
```

Las cuatro afirmaciones son diferentes.

M09 no pretende adivinar qué proveedor, modelo o framework dominará dentro de tres años.

Pretende desarrollar una capacidad más útil:

```text
TECHNOLOGY FORESIGHT
+
ARCHITECTURE JUDGEMENT
```

Es decir:

> detectar un cambio tecnológico, comprender qué capability añade, evaluar qué riesgos introduce y decidir si modifica o no nuestro roadmap.

# 1. De “seguir tendencias” a construir un Technology Radar

Una organización madura no reacciona a cada anuncio.

Mantiene un radar.

Una clasificación sencilla:

```text
NOW
NEXT
WATCH
```

## NOW

Tecnologías suficientemente maduras para evaluar o utilizar hoy.

Ejemplos generales:

- modelos multimodales;
- RAG;
- tool calling;
- agentes limitados;
- modelos pequeños;
- inferencia acelerada;
- NPUs en dispositivo.

## NEXT

Tecnologías disponibles pero todavía en consolidación organizativa o técnica.

Ejemplos:

- agentes con mayor autonomía;
- agent-to-agent workflows;
- memoria de largo plazo más sofisticada;
- edge generativo más capaz;
- plataformas empresariales de evals cada vez más completas.

## WATCH

Tecnologías o patrones cuyo impacto aún es incierto.

Ejemplos:

- arquitecturas alternativas a Transformer en determinados dominios;
- autonomía generalizada;
- nuevos paradigmas de memoria;
- hardware especializado todavía no desplegado ampliamente.

El radar no es una predicción.

Es:

```text
una lista de hipótesis
que revisamos periódicamente
```

# 2. Cinco preguntas para evaluar cualquier tendencia

Ante una nueva tecnología:

## 2.1. ¿Qué capability añade?

Ejemplo:

```text
nuevo modelo multimodal
```

puede añadir:

```text
visión
audio
video
```

No basta:

```text
"es más potente"
```

---

## 2.2. ¿Qué problema empresarial resuelve?

Si no existe un problema:

```text
technology push
```

---

## 2.3. ¿Cuál es su madurez?

Distinguir:

```text
demo
preview
general availability
production evidence
```

---

## 2.4. ¿Qué cambia en riesgo y operación?

Ejemplo:

```text
texto
→ texto + audio + cámara
```

también amplía:

- privacidad;
- almacenamiento;
- attack surface;
- evaluación.

---

## 2.5. ¿Qué sustituye?

Una nueva tecnología puede:

```text
reemplazar
complementar
o no cambiar nada
```

de nuestra arquitectura.

# 3. Tendencia 1 — Multimodalidad

El temario identifica expresamente los modelos multimodales:

```text
texto
imagen
audio
```

En 2026, multimodalidad ya no debe enseñarse como una curiosidad de laboratorio.

Es una capacidad práctica.

---

# 4. ¿Qué significa multimodal?

Un sistema multimodal puede consumir o producir más de un tipo de información.

Entrada:

```text
text
image
audio
video
documents
```

Salida:

```text
text
speech
image
structured data
actions
```

No todos los modelos soportan todas las combinaciones.

---

# 5. Pipeline multimodal tradicional

Antes de modelos multimodales integrados podíamos construir:

```text
audio
 ↓
speech-to-text
 ↓
LLM
 ↓
text-to-speech
```

o:

```text
image
 ↓
OCR / vision model
 ↓
text
 ↓
LLM
```

Este patrón sigue siendo válido.

---

# 6. Modelo multimodal integrado

Arquitectura conceptual:

```text
TEXT ──────────┐
IMAGE ─────────┼──> MULTIMODAL MODEL ──> RESPONSE
AUDIO ─────────┤
VIDEO ─────────┘
```

El modelo trabaja sobre representaciones internas de varias modalidades.

---

# 7. Representaciones multimodales

Idea fundamental:

```text
pixels
waveforms
tokens
```

no tienen la misma representación original.

Necesitamos transformar cada modalidad.

Ejemplo conceptual:

```text
image
 ↓
vision encoder
 ↓
visual tokens / embeddings
```

Audio:

```text
waveform
 ↓
audio encoder
 ↓
audio representation
```

---

# 8. Fusion

¿Cómo combinamos modalidades?

Patrones:

```text
early fusion
late fusion
cross-attention
shared representation
```

En foundation models modernos puede aparecer una representación integrada donde diferentes tipos de tokens participan en mecanismos comunes de atención.

# 9. Multimodal no significa “ver como un humano”

Un modelo puede identificar:

```text
tabla
gráfico
captura
objeto
```

pero puede fallar en:

- detalles pequeños;
- relaciones espaciales;
- conteo;
- texto embebido;
- gráficos complejos.

Necesita evals.

# 36. Multi-agent anti-pattern

No crear:

```text
15 agents
```

porque:

```text
"se parece a una empresa"
```

Más agentes implican:

- más llamadas;
- más estado;
- más coste;
- más debugging.

---

# 37. Specialized agents

# 38. Agent identity



# 39. Agent protocols

# 40. Model Context Protocol — MCP

A septiembre de 2026, MCP dispone de una especificación publicada el 28 de julio de 2026 que refuerza aspectos como núcleo stateless, routing y autorización.

El concepto importante para el curso no es una implementación concreta.

Es:

```text
interoperability
```

entre clientes y servidores de herramientas/contexto.

---

# 41. Protocol ≠ Security

Un protocolo estandariza comunicación.

No sustituye:

- IAM;
- authorization;
- sandboxing;
- audit;
- input validation.

---

# 42. Agent evaluation

- task success;
- tool selection;
- number of steps;
- cost;
- safety;
- unauthorized attempts;
