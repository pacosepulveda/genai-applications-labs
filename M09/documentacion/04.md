# 260. Glosario

**Agent**  
Sistema que utiliza un modelo para seleccionar acciones/herramientas de forma dinámica.

**Autonomy Budget**  
Límites de pasos, coste, tiempo y herramientas permitidas a un agente.

**Edge AI**  
Ejecución de modelos cerca del punto donde se generan los datos.

**HBM**  
High Bandwidth Memory.

**Human-in-the-loop**  
Patrón en el que una persona interviene en una decisión o acción del sistema.

**KV Cache**  
Memoria utilizada durante generación autoregresiva para reutilizar información de atención.

**MCP**  
Model Context Protocol; protocolo de interoperabilidad entre aplicaciones/modelos y fuentes de herramientas/contexto.

**Mixture of Experts**  
Arquitectura que activa solo parte de un conjunto de expertos para cada entrada/token.

**Multimodal**  
Sistema capaz de trabajar con más de una modalidad de información.

**NPU**  
Neural Processing Unit.

**Personalization**  
Adaptación de contexto, output o comportamiento a organización, rol, usuario o tarea.

**Quantization**  
Reducción de precisión numérica para mejorar eficiencia.

**SLM**  
Small Language Model.

**State Space Model**  
Familia de modelos secuenciales que utiliza representaciones de estado como alternativa o complemento a atención.

**Technology Radar**  
Herramienta para clasificar tecnologías según madurez y estrategia de adopción.

**TPU**  
Tensor Processing Unit.

# 261. Ideas clave que deben quedar al terminar M09

1. El futuro no se gestiona intentando acertar predicciones.
2. Se gestiona construyendo capacidad de evaluación y adaptación.
3. Multimodalidad ya es una capability práctica.
4. Cada modalidad añade valor y superficie de riesgo.
5. Video/audio requieren decisiones de sampling, streaming y privacidad.
6. Los agentes deben ganar autonomía de forma progresiva.
7. Más agentes no significa mejor sistema.
8. Tools y permisos determinan el impacto real de un agente.
9. Protocolos de agentes mejoran interoperabilidad, no sustituyen seguridad.
10. Personalización debe usar el mínimo contexto útil.
11. Memory es información gobernable.
12. Edge AI aporta privacidad, latencia y offline, pero tiene límites.
13. El futuro será frecuentemente híbrido edge/cloud.
14. Model compression hace posible más inferencia local.
15. GPU, TPU y NPU resuelven necesidades distintas.
16. Memoria y red son tan importantes como compute.
17. Hardware y software evolucionan mediante co-design.
18. MoE busca ampliar capacidad con activación dispersa.
19. SSM y otras arquitecturas merecen seguimiento sin anunciar el fin del Transformer.
20. Long context y RAG son complementarios.
21. Model routing puede optimizar calidad, coste, riesgo y latencia.
22. Regulación debe gestionarse como capability recurrente.
23. El AI Act ya tiene nuevas obligaciones efectivas en 2026.
24. Compliance debe generar evidence.
25. Sostenibilidad necesita métricas por tarea.
26. Modelo más grande no siempre produce mejor resultado empresarial.
27. Caching, batching, quantization y routing pueden reducir consumo.
28. Human oversight solo funciona si el humano puede intervenir realmente.
29. Human + AI debe evaluarse, no asumirse superior.
30. Portable eval sets son un activo estratégico.
31. Arquitecturas futuras deben desacoplar modelo, retrieval, tools y policy.
32. Abstracción excesiva también tiene coste.
33. Vendor lock-in se gestiona midiendo switching cost.
34. Scenario planning es mejor que un forecast único.
35. Technology Radar debe permitir ADOPT, TRIAL, WATCH, REJECT y RETIRE.
36. La principal skill de futuro es aprender y evaluar nuevas capacidades rápidamente.
